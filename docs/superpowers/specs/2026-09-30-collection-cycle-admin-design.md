# 수집 사이클 Admin 설계

날짜: 2026-09-30  
상태: 초안 (브레인스토밍 승인 반영)  
범위: `packages/web-api` — 기간·유형 하나의 수집 사이클을 리드와 여섯 단계 페이지로 수행한다.  
구현 계획이 아니라 **화면 자리·데이터 흐름·오류·테스트 경계**다.

운영 흐름은 [`docs/collection-cycle.md`](../../collection-cycle.md)다. 이 스펙은 그 흐름을 Admin에서 따라가게 만드는 화면이다.

## 1. 목표

운영자가 한 기간·한 보고서 유형을 고르고, 수집 → 추출 → 실패 검토 → 로직 메모 → 보완 → 다음 수집 순서로 일한다.

성공 기준:

- `/admin/cycle`에서 기간과 유형을 고르면 여섯 단계의 숫자가 그 범위만 센다.
- 1·2·6번은 짧은 상태 페이지이고, 수집·추출 작업은 지금 화면으로 넘어간다.
- 3번은 실패 모양마다 원문 5건과 판정·메모 하나다. 저장하면 그 기간의 같은 모양 전체가 그 판정으로 집계된다.
- 4번은 로직 메모 목록이다. 파서를 고치지 않는다.
- 5번은 로직 모양이 있는 문서만 통째로 다시 추출한다. 소스만 있는 문서는 뺀다.
- 판정 저장은 facts와 카탈로그를 바꾸지 않는다.

## 2. 확정된 전제

| 항목 | 결정 |
|------|------|
| 자리 | 기존 Admin. 메뉴 **사이클**을 수집·추출·검토 옆에 둔다. 그 셋은 그대로다 |
| 인증 | 다른 Admin HTML과 같은 토큰 쿠키. 없으면 `/admin/token` |
| 화면 | 기존 Admin과 같은 서버 HTML |
| 범위 | 시작일·종료일 8자리, 유형은 F001·F002·A001 중 하나. 양 끝 포함 |
| 검토 메뉴 | `/admin/reviews`는 성공 값의 이상·드문 코드 검토다. 이 사이클의 실패 분류와 저장을 공유하지 않는다 |
| 기존 `patch` | 추출 화면의 `patch`는 칸 실패 문서 전체를 다시 읽는 지금 동작 그대로다. 5번은 그 모드를 바꾸지 않고, 로직 문서만 고른 별도 실행이다 |
| 원문 | 새 탭의 DART 문서 주소(`DART_DOCUMENT_VIEW`). 서버가 DART를 호출하지 않음 |
| 파서 | 화면이 규칙을 고치지 않는다. 칸 하나만 다시 읽지 않는다 |
| Viewer 요약 | 이 스펙에 없다. 나중 Viewer가 읽을 결과는 facts와 이 스펙의 모양 판정이다 |

회사 업종 보강, 태그, 이상값 진단, 다음 기간으로의 판정 복사는 하지 않는다.

## 3. 화면

공통 쿼리는 `start_date`, `end_date`, `report_type`이다. 단계 링크는 이 셋을 유지한다.

| 단계 | 경로 | 하는 일 |
|------|------|---------|
| 리드 | `GET /admin/cycle` | 기간·유형 폼과 여섯 줄 |
| 1. 수집 | `GET /admin/cycle/collect` | 수집 상태. 작업 링크는 `/admin?report_type=` |
| 2. 추출 | `GET /admin/cycle/extract` | 네 가지 칸 결과. 작업 링크는 지금 추출 화면의 기간·유형 인자 |
| 3. 실패 검토 | `GET /admin/cycle/failures` | 칸별 건수, 모양, 대표 원문, 판정 폼 |
| 4. 로직 | `GET /admin/cycle/logic` | 로직 모양과 메모. 판정은 바꾸지 않고 3번으로 돌아간다 |
| 5. 보완 | `GET /admin/cycle/patch` | 대상 문서 수와 실행 |
| 6. 다음 수집 | `GET /admin/cycle/next` | 다음 시작일·종료일. 유형은 현재 값이고 바꿀 수 있다 |

6번을 진행하면 새 기간의 1번으로 간다. 이번 기간의 판정은 복사하지 않는다.

리드 숫자의 단위는 단계마다 다르다.

| 단계 | 리드 숫자 | 단위 |
|------|-----------|------|
| 1 | 목록으로 확인한 공시 중 수집이 끝나지 않은 수 | 공시 |
| 2 | 수집된 대상 문서 중 현재 추출기 `ok`가 아닌 수 | 문서 |
| 3 | 판정이 없는 실패 모양 수 | 모양 |
| 4 | 로직으로 저장된 실패 모양 수 | 모양 |
| 5 | 다시 추출할 문서 수 | 문서 (`rcept_no`+`dcm_no`) |
| 6 | 없음 | |

1번의 리드 숫자 0은 확인된 목록 안에 남은 공시가 없다는 뜻이다. 목록을 아직 받지 않은 날은 그 숫자에 넣지 않고, 1번 페이지에 「목록을 아직 확인하지 않은 날」로 보여 준다. 확인된 날의 미완료는 그 슬라이스의 `listed_count - succeeded`다. `listed_count`가 없으면 그 날은 미확인이다.

2번의 대상 문서는 그 기간·유형에 대해 추출 완전성 화면과 같은 집합이다. 리드 숫자는 그중 현재 추출기 `ok`가 아닌 문서다. 2번 페이지의 성공·해당없음·제도상없음·실패는 그 `ok` 문서의 칸 결과이고, 문서 수와 더하지 않는다. 문서를 가져오지 못한 건은 네 가지 칸 결과에 넣지 않는다.

## 4. 실패 모양과 저장

실패 칸만 센다. 잘 읽힌 문서(`fetch_status=ok`, 현재 `EXTRACTOR_VERSION`)에서 `classify_outcome`이 `fail`인 칸이다. 해당없음과 제도상없음은 실패가 아니다.

모양 키는 칸(`field_bundles.BUNDLE_KEYS`)과 `_failure_subject` 문자열이다. 문자열은 `상태|missing=0 또는 1|conflicts=0 또는 1`이다. 상태가 없으면 `None`이다.

저장 테이블은 `failure_shape_judgments`다. `extraction_reviews`에 쓰지 않는다.

한 행의 키는 `start_date`, `end_date`, `report_type`, `bundle`, `shape`다. 값은 `verdict`(`source` 또는 `logic`)와 `note`다. 행이 없으면 처리전이다. 처리전으로 되돌리는 저장은 그 행을 지운다.

대표 원문은 그 기간·유형·모양에서 접수일 내림차순 최대 5건이다. 접수일이 없으면 뒤로 간다. 같은 접수일이면 `rcept_no`, `dcm_no` 내림차순이다. 연구 패널로 거르지 않는다.

로직 저장은 `note`가 비어 있지 않아야 한다. 소스는 빈 메모도 된다. 저장은 그 키 하나에만 영향을 주고, 같은 모양의 다른 기간 행은 그대로다. 집계는 그 기간에 지금 그 모양으로 실패하는 칸 수에 이 판정을 붙인다. 문서마다 판정 행을 만들지 않는다.

## 5. 보완

대상은 그 기간·유형의 현재 추출기 `ok` 문서 중, 실패 칸이 하나라도 로직 모양인 문서다. 실패가 소스뿐이거나 처리전뿐인 문서는 뺀다. 소스 모양과 로직 모양이 같이 있으면 대상에 넣는다.

실행은 그 문서 목록으로 추출 잡을 만든다. 문서를 통째로 다시 읽는다. 추출 잡이 `pending` 또는 `running`이면 시작하지 않는다. 대상이 0이면 잡을 만들지 않고, 대상이 없다는 안내만 보여 준다.

다시 읽은 뒤 그 실패 모양이 남아 있으면 판정과 메모는 유지된다. 모양이 사라지면 집계에서만 빠지고, `failure_shape_judgments` 행은 지우지 않는다.

## 6. 오류

- 날짜가 8자리 숫자가 아니거나 시작일이 종료일보다 늦다. 리드로 돌려보내고 이유를 보여 준다. 저장과 보완은 하지 않는다.
- `report_type`이 F001, F002, A001이 아니다. 같은 방식으로 거절한다.
- 로직인데 메모가 비어 있다. 그 모양 화면에 이유를 보여 주고 행을 쓰지 않는다.
- 추출 잡이 진행 중이다. 보완을 시작하지 않고 이유를 보여 준다. 판정 행은 그대로다.
- 보완 대상이 0건이다. 잡을 만들지 않는다.

## 7. 테스트

앱 클라이언트와 SQLite 메모리 DB를 쓴다. DART는 호출하지 않는다.

- 대표를 로직으로 저장하면 그 기간의 같은 모양 전체 건수가 로직이다. 다른 기간의 같은 모양은 처리전이다.
- 소스만 있는 문서는 보완 대상에 없고, 소스 모양과 로직 모양이 같이 있는 문서는 있다.
- 해당없음·제도상없음 칸은 실패 건수와 모양 목록에 없다.
- 빈 메모의 로직 저장은 행을 만들지 않는다. 소스의 빈 메모는 저장된다. 처리전 저장은 행을 지운다.
- 진행 중인 추출 잡과 0건 대상은 잡을 만들지 않는다.
- 판정 저장은 `audit_report_facts`, 카탈로그, `extraction_reviews`를 바꾸지 않는다.
- 1번 리드 숫자는 확인된 목록의 미완료 공시만 센다. 목록을 받지 않은 날은 1번 페이지에만 나온다.
- 잘못된 날짜·유형은 저장하지 않고 리드에서 이유를 보여 준다.

## 8. 비범위

Viewer 요약 화면, 칸 단위 재추출, 화면에서의 파서 수정, `/admin/reviews`의 포함 규칙, 추출 화면 `patch`의 대상 변경, 판정을 다음 기간에 복사하기, 회사 업종.
