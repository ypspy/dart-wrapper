# 연구 자료 완성 조건

날짜: 2026-09-10  
목적: 「업종까지 넣었으니 연구가 되나」를 층으로 나누고, 층마다 **완료 판정 기준**과 **할 일**을 적어 계획을 세운다.

완성 조건은 연구 질문 하나에 대해 닫힌다. 질문이 바뀌면 아래 표의 「필수/선택」이 바뀐다. **§1은 2026-09-10에 잠갔다.** 이번 연구의 주력은 **A층(원문 감사 구성개념)과 B층(규모 등 계정 통제) 둘 다** 이다. B층 숫자의 주 출처는 상용 DB가 아니라 **추출 `accounts`(총자산)**.

---

## 0. 세 층을 섞지 않는다

| 층 | 질문 | 여기서 닫는 것 | 여기서 안 닫는 것 |
|----|------|----------------|-------------------|
| **L1. 파이프라인** | DART에서 약속한 원문 변수가 DB에 재현 가능한가 | 카탈로그·추출·회사 마스터의 입수 완전성, 버전, 상태 플래그 | 키인 재무, 주가, 감리, 산업 이력 |
| **L2. 분석 패널** | 기업–연도(또는 문서) 회귀에 넣을 표가 있는가 | 정정 접기, `corp_code` 조인, 상장/산업 통제 열 | 논문 심사자가 믿을 대사표 |
| **L3. 측정 방어** | 기계 추출을 키인/XBRL과 같은 자리에 두지 않고도 설득되는가 | 골드셋, 계정 대사, 표본 각주 | 새 추출기(D-7, 중요성 5절 등) |

**전체 완성** = 연구 질문이 쓰는 열에 대해 L1∩L2∩L3가 모두 초록.  
업종 잡만 끝난 상태는 L1의 **한 칸**이다.

## 1. 고정한 연구 설계 (이 값이 모든 필수 조건을 가른다)

잠금일: 2026-09-10. 아래가 바뀌면 L1–L3의 필수/선택을 다시 적는다.

| 결정 | 잠근 값 | 운영·완성 함의 |
|------|---------|----------------|
| 관심 계수 | **둘 다.** A층(의견/ICFR/GC/시간) + B층(규모 등 계정) | A층은 추출이 주 자료. B층도 이번엔 추출 계정. 골드셋(V3)과 계정 결측 방침(E·P3)이 둘 다 필수 |
| 표본 기간 | **결산월 `year_end` 2016-01-31 ~ 2025-12-31.** 1월말부터 12월말까지 **모든 결산월** 포함(12월말만 아님). 원 표현: 「2016년 1월말 회계법인부터 2025년 12월 회계법인까지」= 결산법인 | 분석 필터는 `year_end`. 카탈로그 슬라이스는 **접수일**. 권장 접수 창: **2016-01-01 ~ 2026-09-09**(한국시간 어제). 2025-12 결산의 지연 접수를 넣기 위함 |
| 공시 유형 | **F001, F002, A001**(A001은 첨부 감사·연결감사 포함) | C1 유형 칩이 이 셋과 같아야 함. 추출 대상도 동일 |
| 상장 범위 | **비상장 포함** (유가·코스닥으로 자르지 않음) | `corp_cls`는 **현재** 값. 표본 기간 중 상장·폐지 이력은 없음 → 각주. 상장만 강건성은 V6 선택 |
| 정정 | **최종 접수만** (정정 사건 연구 아님) | 입수는 이력 유지. 패널에서 `corp_code`+`year_end`(+선택한 `fs_scope`)의 **최신 `rcept_dt` 1건**. 재수집 필수는 아님(C4) |
| 별도·연결 | **연결이 있으면 연결, 없으면 별도.** 기업–연도 **한 행** | `fs_scope=consolidated`(F002 또는 A001 연결감사)가 있으면 그것. 없으면 `separate`(F001 또는 A001 감사). 같은 범위에서 F전용과 A001 첨부가 겹치면 **F001/F002 우선** |
| 산업 통제 | **현재 KSIC** (`corps.induty_code`) | 업종 이력 없음(I4). 코드만 쓰면 I3(전 표 이름)는 선택 |
| 규모 통제 | **추출 총자산** (`accounts` 자산총계, `value_won`) | 비상장은 XBRL 없음. **KIS·NICE 등 외부 DB 서비스를 쓰지 않음.** 추출 실패·결측은 그 행을 주 회귀에서 제외하고 N을 각주. 「키인·XBRL과 동등한 검증」은 주장하지 않음 |

**접수 창이 `year_end`보다 넓은 이유.** 2016-01 결산 감사보고서는 대개 2016년 접수, 2025-12 결산은 2026년 접수다. 슬라이스 complete는 접수일로 판정하고, 회귀 표본은 `year_end`로 자른다. 창 밖의 조기·초지연 접수는 표본 흐름도에 잔여로 적는다.

## 2. L1 — 파이프라인 완성 조건

### 2.1 카탈로그 (입수)

**상태: C1–C5 완료 (2026-09-10).** 접수일 2016-01-01~2026-09-09 × F001/F002/A001.

완료로 보려면 **선택한 유형 × 선택한 날짜 범위**에서 다음이 동시에 참이어야 한다.

| # | 조건 | 확인 방법 | 할 일 | 상태 |
|---|------|-----------|--------|------|
| C1 | 대상 유형이 모두 수집됨 | Admin 히트맵·슬라이스. 유형 칩이 연구 설계와 같음 | 빠진 유형 `POST /admin/catalog/extract` | 완료 |
| C2 | 각 유형·각 날짜 슬라이스가 `complete` | 목록 건수 = 성공, 실패 0 | `blocked`/`partial`은 resume·retry | 완료 |
| C3 | 당일 미도래 칸을 「완료」로 세지 않음 | 한국시간 당일은 투명 | 접수 창 끝 = 2026-09-09(잠금 시점의 어제). 이후 날짜는 표본에 안 넣음 | 완료 |
| C4 | 정정 전·후가 설계와 맞음 | 입수는 이력 포함이 맞음 | **최종만은 export/패널에서 필터.** 재수집(`finalReport: recent`)은 하지 않음 | 완료 |
| C5 | 첨부 접수 스코프가 반영된 수집임 | option `rcpNo` = 현재 접수만 | 옛 규칙(이름별 최신 첨부)이면 최종 행도 오염될 수 있음 → 그 구간만 재수집. 정정 사건 연구는 아님 | 완료 |

입수 L1-C는 닫혔다. 이후 할 일은 패널에서 최종 접수만 고르는 것(P1)이며, 카탈로그 재수집이 아니다.

### 2.2 감사 추출 (facts)

카탈로그가 있는 같은 범위에 대해:

| # | 조건 | 확인 방법 | 할 일 |
|---|------|-----------|--------|
| E1 | 추출기 버전 고정 | 행마다 `extractor_version = audit_opinion.v19` (또는 논문에 적은 버전) | 버전 올린 뒤 전 범위 `extract`/`reparse` 정책 결정 |
| E2 | 대상 문서 대비 `unextracted` ≈ 0 | `GET .../completeness` | 기간·유형별 extract 잡 |
| E3 | `fetch_failed`/`blocked`/`section_missing` 처리 방침 | 재시도 후 남은 건수 기록 | resume. 잔여는 표본에서 제외한다고 각주 |
| E4 | `field_partial` 방침 | 4절 없는 옛 공시를 넣을지 | **넣으면** 4절을 제외 조건에서 뺌. **빼면** 과거 연도가 체계적으로 줄어듦 |
| E5 | `audit_report_date` | `ambiguous` 비율, 수동/LLM 비율 | `resolve-dates` 또는 PATCH. 미해소는 분석에서 제외 여부 |
| E6 | 수집과 추출을 동시에 안 돌림 | 운영 규칙 | 카탈로그 닫은 뒤 추출 |
| E7 | 규모 통제용 자산총계 | 주 회귀에 넣을 행의 `accounts` 자산총계 `ok` | 실패·없음은 제외하고 N 각주. 추출이 규모 열의 출처 |

**업종 잡과 독립:** 업종이 `ok`여도 E2가 비어 있으면 L1 미완성.

### 2.3 회사 마스터 (업종)

**상태: I1–I4 완료 (2026-09-11).** 공시 distinct `corp_code` 71,359 · `ok` 71,359 · remaining 0.
I5(Catalog/Facts 업종 필터)는 1차 범위 밖이며 L1 닫힘에 넣지 않는다.

완료로 보려면 다음이 동시에 참이어야 한다.

| # | 조건 | 확인 방법 | 할 일 | 상태 |
|---|------|-----------|--------|------|
| I1 | 공시 distinct `corp_code` 대비 잔여 0 (또는 잔여 사유 목록) | `/admin/corps/summary` remaining | remaining=0. `ok`이지만 업종코드 없음 20건(API `000`·코드 NULL)은 잔여가 아님 | 완료 |
| I2 | 호출 한도·RST에 안 걸림 | 분당 200·동시 2 | 이번 fill은 remaining 0으로 끝남. 이후 호출도 같은 한도 | 완료 |
| I3 | KSIC **이름**이 연구에 필요하면 전 코드표 | 11차 우선(`ksic11.json`) → 없으면 10차(`ksic10.json`). 표 간 parent 사슬은 섞지 않음 | remap 71,339건 이름 채움. 코드 없는 20건만 이름 NULL | 완료 |
| I4 | 「현재 스냅샷」임을 설계에 적음 | §1에 적음. 이력 없음 | 연도별 산업은 **안 함**. 외부 산업 이력은 L2 필수에서 제외 | 완료 |
| I5 | Catalog/Facts 필터 | 1차 범위 밖(스펙) | 분석은 SQL/`corp_code` JOIN으로 가능. UI JOIN은 편의, 완성 필수는 아님 | 범위 밖 |

입수 L1-I는 닫혔다. `stock_code`·`corp_cls`는 **현재** 상장 구분이다. 표본 기간 중 상장·폐지는 I 테이블만으로 완성되지 않는다 (→ L2).

### 2.4 L1 닫는 한 줄

> 연구 설계의 유형·기간에서 슬라이스 complete, 추출 completeness의 잔여가 방침대로 0에 가깝고, 공시 회사의 업종 `ok`(또는 문서화된 실패), 추출기 버전이 한 값으로 고정.

## 3. L2 — 분석 패널 완성 조건

파이프라인 행을 회귀용 표로 접는 단계. 규모·산업은 파이프라인 열이다. Big N 매핑과 접기 스크립트는 연구자 쪽이다.

| # | 조건 | 할 일 | 담당 |
|---|------|--------|------|
| P1 | 문서 행 → 분석 단위 | (i) `year_end` ∈ [2016-01, 2025-12] (ii) 유형 F001/F002/A001 (iii) 최신 `rcept_dt` (iv) 연결 있으면 연결, 없으면 별도 (v) 같은 범위 F전용 > A001 첨부 | 연구자 |
| P2 | 식별자 조인 | `corp_code` + `year_end`. 상호 문자열 조인 금지 | 연구자 |
| P3 | 규모 통제 | 추출 자산총계 `value_won`. `accounts_status` 실패·자산총계 없음 → 주 회귀 제외. **KIS·NICE·유료 DB 조인 없음** | 파이프라인 facts |
| P4 | 산업 통제 | `corps.induty_code` (현재 KSIC). 코드 FE. 이름 표는 선택 | 파이프라인 |
| P5 | 상장 범위 | 비상장 포함이므로 `corp_cls`로 표본을 자르지 않음. 현재값 한계는 각주. 상장만 강건성은 V6 | 연구자 |
| P6 | 감사인 특성 | Big N, 법인 변경, tenure | `auditor_resolved` + **매핑 사전**(연구자) |
| P7 | 연구 질문이 요구하는 기타 | 주가, 감사보수 키인, 지배구조, 감리, 지분 | 전부 외부. 파이프라인 완성 조건 아님 |
| P8 | export | TSV/API로 facts∩disclosures∩corps | `export_audit_report_facts.py` + corps JOIN 스크립트 |

**L2 닫는 한 줄:** 주 회귀 명세의 모든 열이 출처와 조인 키와 결측 규칙과 함께 코드북에 있다.

## 4. L3 — 측정 방어 완성 조건

기계 추출 챌린지를 받기 전에 닫는다. §11과 같음.

| # | 조건 | 할 일 | 산출 |
|---|------|--------|------|
| V1 | 변수 층 분리 문장 | A층=추출 주 자료. B층 규모=추출 총자산(외부 DB 없음). 키인 동등 검증은 주장하지 않음 | 논문 측정 절 |
| V2 | 계정 대사 | **전수 키인 대사 없음.** 상장 층화 **소표본**만 OpenDART/XBRL 자산총계와 비교(주 통제는 추출값, 표는 측정 오차 공개). 비상장은 원문 골드셋(V3)으로 격자 읽기만 확인 | 부록 표 |
| V3 | 원문 골드셋 | 연도×유형×서식(선행/후행)×상장/비상장 층화. 의견·ICFR·GC·감사인 + **자산총계 칸** 원문 대조 | 부록 일치율 |
| V4 | 골드셋 HTML 보관 | 전량 저장 없이 V2·V3 표본만 viewer HTML | 재현 패키지 |
| V5 | 버전·필터 각주 | `v17`, `fetch_status=ok`, `field_partial` 처리, ambiguous 날짜 | 표본 구축 절 |
| V6 | 강건성 목록 | 상장만(XBRL 존재) / 골드셋·상장 대사 일치만 / reparse 전후 / 12월말 결산만 | 분석 계획 |

**L3 닫는 한 줄:** A층은 원문 골드셋, B층 규모는 추출 총자산임을 명시하고, 상장 소표본 XBRL 대사로 읽기 오차를 공개한다. 비상장·유료 DB 전수 대사는 없다.

## 5. 명시적으로 완성에서 빼는 것 (범위 밖)

계획에 「안 함」으로 적어 두어야 끝없이 안 늘어난다.

- 실시내용 **5절 중요성 금액**
- 정관 OCR (D-7)
- 업종 **이력** 테이블 (§1: 현재 KSIC)
- OpenDART 재무제표 API를 주 계정으로 파이프라인에 넣기 (상장 소표본 대사는 L3, 주 회귀 열 아님)
- 원문 HTML **전량** 아카이브
- Catalog/Facts 화면 업종 필터 (분석 JOIN으로 대체 가능)
- 감리·주가·지배구조 수집
- KIS·NICE 등 **외부 DB 서비스**
- 추출 총자산을 키인·XBRL과 **동등하게 검증된 숫자**라고 주장 (사용은 하되 주장은 안 함)

나중에 넣으면 그때 L1 또는 L2에 **새 줄**을 추가한다.

## 6. 권장 작업 순서 (계획용)

의존성 순이다. 병행 가능한 것만 표시했다.

```text
0. 연구 설계 표(§1) — 잠김 (2026-09-10)
1. OpenDART 웹 RST 해제 확인 — 이번 fill은 remaining 0으로 닫힘 (I2, 2026-09-11)
2. L1-C 카탈로그: 접수일 2016-01-01~2026-09-09 × F001/F002/A001 — 완료 (C1–C5, 2026-09-10)
3. L1-E 감사 추출: completeness + 날짜 ambiguous 방침 (자산총계 결측 방침 포함)
4. L1-I 업종 fill-missing — 완료 (I1–I2, 2026-09-11)
5. KSIC 전 표(I3) — 완료 (2026-09-11). 11차 우선·10차 폴백. 기존 행 이름은 remap 스크립트
6. L2: 최종 접수 접기 + 연결우선 한 행 + 추출 총자산 + Big N 매핑
7. L3: 골드셋 층화(비상장 포함) → 수동 대조 → 상장 소표본 XBRL 대사
8. 골드셋 HTML만 아카이브
9. 코드북 + 표본 흐름도(N이 줄어드는 이유: 정정 접기, 연결우선, 자산 결측, field_partial)
```

운영 제약: **카탈로그 수집과 감사 추출은 한 프로세스에서 동시에 금지.** 업종 잡은 DART 잠금과 분리되어 있어 수집/추출과 동시에 돌릴 수 있다. OpenDART는 분당 200·동시 2.
